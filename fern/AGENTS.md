# AGENTS.md — Forest-OS Build System Guide for AI Agents

Naming: **Fern** is the kernel component; **Forest-OS** is the whole OS (Fern +
the foreboots bootloader + the forestlibs C library). Build variables/outputs
use `FERN_*` / `fern.elf` for the kernel image.

This document describes how the Forest-OS build is configured and driven, and
what commands to run when modifying build-system files. Read this before
touching `conf.sh`, `build-config.mk`, `Makefile`, or anything under `build/`.

## Config Flow (three layers)

```
.forestos_config  ──[conf.sh --generate]──▶  build-config.mk  ──[Makefile include]──▶  build/*.mk
   (Kconfig source)                           (build-time truth)                       (fragments)
```

1. **`.forestos_config`** — human/Kconfig source of truth. Format: `CONFIG_<NAME>=<value>` where bools are `y`/`n`.
2. **`build-config.mk`** — GENERATED by `conf.sh --generate`. The Makefile includes this first. Never hand-edit. Bools are `yes`/`no` here (not `y`/`n`).
3. **`build/*.mk`** — makefile fragments included by the main `Makefile`; each owns one concern. Feature fragments append to shared variables (`EXCLUDED_CSOURCES`, `QEMU_OPTS`, etc.) gated by `ifeq ($(ENABLE_X),no)`.

`make` uses `build-config.mk` as the source of truth. CLI `make ARCH=64` still overrides per standard make semantics (CLI > makefile default).

## Build / Config Commands

| Command | Purpose |
|---|---|
| `./conf.sh --menuconfig` | Interactive TUI configuration (writes `.forestos_config` + regenerates `build-config.mk`) |
| `./conf.sh --defconfig` | Sane defaults (writes `.forestos_config` + regenerates `build-config.mk`) |
| `./conf.sh --oldconfig` | Re-validate existing `.forestos_config`, regenerate `build-config.mk` |
| `./conf.sh --allnoconfig` | All bools `n` (except required-on), save + generate |
| `./conf.sh --allyesconfig` | All bools `y`, save + generate |
| `./conf.sh --generate` | Regenerate `build-config.mk` from current `.forestos_config` (no UI) |
| `make menuconfig` / `make defconfig` / `make oldconfig` | Phony targets that invoke `conf.sh` |
| `make configcheck` | Validate `build-config.mk` vs `.forestos_config`; print effective config |
| `make show-config` | Full effective config dump |
| `make` | Build per `build-config.mk` (NOT hard-coded defaults) |
| `make ARCH=64 BOOT_MODE=uefi` | CLI override still wins (make semantics) |

Shell consumers (`run.sh`, `build-helper.sh`, `build-dist.sh`) load config via:
```bash
eval "$(./tools/config-env.sh)"   # exports ARCH, BOOT_MODE, BUILD_TYPE, ENABLE_*, QEMU_*, ...
```
`tools/config-env.sh` exits non-zero if `build-config.mk` is missing; consumers wrap with `|| true` / a fallback block.

## `build/` Include Structure

The main `Makefile` is a thin orchestrator that includes fragments in order:

```
build/config.mk            # load build-config.mk, validate, default bools to no, assemble FEATURE_FLAGS, configcheck
build/dirs.mk              # directory layout, arch suffix logic
build/toolchain.mk         # per-arch toolchain detection
build/flags.mk             # CFLAGS/LDFLAGS/numeric -D tunables/build-type/NASM/linker
build/kernel-sources.mk    # EXCLUDED_CSOURCES base, CSOURCES/COBJECTS, subsystem object lists, ALL_OBJECTS
build/features/*.mk        # one per subsystem; gate sources via ifeq ($(ENABLE_X),no)
                           #   memory, filesystems, graphics, networking, audio, usb, storage,
                           #   input, ipc, timers, interrupts, security, hardware, scheduler,
                           #   canopy, compat
build/userspace.mk         # userspace apps conditional on USERSPACE_*/CANOPY_*
build/qemu-run.mk          # run/run-bios/run-uefi/run32/run64/... driven by QEMU_* + ENABLE_TESTING
build/iso.mk               # ISO/IMG rules, honors GRUB_TIMEOUT + ENABLE_FOREB_BOOTLOADER
build/foreb.mk             # ForeB targets, honors ENABLE_FOREB_BOOTLOADER
build/clean.mk             # clean/clean-all + CLEAN_BEFORE_BUILD pre-build hook
```

### Shared variables feature fragments append to (do NOT redefine)
- `EXCLUDED_CSOURCES`, `EXCLUDED_GRAPHICS_SRCS`, `EXCLUDED_INPUT_SRCS`, `EXCLUDED_USB_SRCS`, `EXCLUDED_FS_SRCS`, `EXCLUDED_INTERRUPT_SRCS`, `EXCLUDED_CANOPY_SRCS`
- `KERN_EXTRA_OBJS`, `USERSPACE_EXCLUDED`, `QEMU_OPTS`

Gating convention: `ifeq ($(ENABLE_FOO),no) EXCLUDED_CSOURCES += $(SRCDIR)/foo.c endif`. Each fragment verifies source files exist (`$(wildcard ...)`).

## Verification (run after ANY build-system change)

These do not require a toolchain and confirm the config plumbing is intact:

```bash
bash -n conf.sh                                  # shell syntax check
./conf.sh --defconfig                            # writes .forestos_config + build-config.mk
make configcheck                                 # validate config
make -n build                                    # dry-run; confirms includes resolve + gating works
make show-config                                 # full effective config dump
```

Also recommended after editing shell helpers:
```bash
bash -n tools/config-env.sh
bash -n build-dist.sh
eval "$(./tools/config-env.sh)" && echo "ARCH=$ARCH BOOT_MODE=$BOOT_MODE BUILD_TYPE=$BUILD_TYPE"
```

## Lint

There is no formal linter. Use:
- `bash -n <script.sh>` for shell scripts (`conf.sh`, `tools/config-env.sh`, `build-dist.sh`, `run.sh`, `build-helper.sh`).
- `make -n <target>` for makefiles (dry-run reveals include/gating errors without needing the toolchain).
- Grep checks (run by orchestrator): no duplicate `ARCH :=`, no orphan `TYPE :=`, `FEATURE_FLAGS` contains no process options (`CLEAN_BEFORE_BUILD`, `VERBOSE`, `WERROR`, `QEMU_*`, `GRUB_TIMEOUT`, `GENERATE_CHECKSUMS`, `ENABLE_TESTING`, `ROOT_AUTOLOGIN`, `BUILD_PARALLEL_JOBS`).

## Key Contracts

- `ARCH` / `BOOT_MODE` / `BUILD_TYPE` appear EXACTLY ONCE in `build-config.mk`.
- Bools are `yes`/`no` in `build-config.mk` (Makefile gates on `ifeq ($(X),yes)`). `conf.sh` converts `y`→`yes`, `n`→`no`.
- `FEATURE_FLAGS` contains `-D<NAME>` ONLY for `class=feature` bools (gate C code via `#ifdef`). Process/runtime bools are NOT in `FEATURE_FLAGS`. `ROOT_AUTOLOGIN` is handled explicitly by the Makefile as `-DENABLE_ROOT_AUTOLOGIN`.
- Dependency enforcement: if a parent is `no`, children are forced `no` (e.g. `ENABLE_VFS=no` ⇒ all `ENABLE_EXT2/FAT32/...` = `no`). `conf.sh` resolves this before emitting.
- `tools/config-env.sh` exports values verbatim (`yes`/`no`/numbers/strings); consumers normalize to `true`/`false` if needed.
